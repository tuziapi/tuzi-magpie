版本：TM-LOCAL-1.0。日期：2026-11-02。状态：用户已确认产品边界，供新开发会话执行；本会话只整理交接文档，不表示已启动业务开发。

## 1 目标与文档优先级

在现有 Magpie 源码上实现完整兔子业务接入，交付可在当前 macOS 本地运行、供用户验收的 tuzi-magpie。包括全部四 Tab 账户中心、Key 到 Provider/Agent 的配置、主站/Coding/GACCode 三类线路、兔子图片 API 接入及独立应用与发行准备。M0～M3 是实施顺序，不是可以提前结束任务的交付范围。

依据用户“这三点按推荐执行”的确认：新增账户中心本轮只覆盖桌面端；四项可选功能不做；最终目标为本地开发交付，不是生产验收或发布。

用户追加要求：本次是基于 Magpie 的增量接入，原有功能尽可能不受影响，原前端页面尽可能保持完全一致，只增加兔子相关内容。第 2.3 节与 AC-16 将此要求作为强制设计及验收约束。

执行优先级：用户后续明确指令 > 本文冻结范围与验收 > [接入方案](tuzi-mapie-integration-analysis.md) > Word 产品简版。兔子账户业务遵循 [system-token-v1](api-contract.md) 和 [当前账户开放记录](account-workspace-opening.md)，最新 ACCOUNT-OPEN-01～06 覆盖旧 Phase 1 描述。其他仓库的历史任务分支、发布授权、隐藏状态不能套用于新任务。适用仓库规范仍需阅读并遵守；有冲突时按指令层级处理，不把所有历史文字都当新授权。

产品实现参考与接入方案是具体行为依据，Word 是阅读摘要。不得仅凭摘要遗漏高级 Key 条件、价格和状态语义、恢复及凭证边界。

## 2 固定范围

### 2.1 必做

- 应用显示名 `tuzi-magpie`，保留 Magpie 原应用图标、主要交互和原有能力。新增“兔子账户”，进入账户时默认 API 密钥页；应用整体启动页沿用上游习惯，不额外强制改为账户页。这是保留上游交互的实施默认值。
- 桌面四 Tab：API 密钥、调用明细、模型广场、模型服务状态。四概要只在密钥页，无独立总览、无账户设置公开入口。
- 系统令牌连接、检查连接、重启恢复、断开/切号、条件预填、离线和失效处理；独立本地 JSON 保存，不共享助手文件。
- 完整 Key 管理与高级限制，完整消费汇总/趋势、模型筛选/分组目录价格、服务状态与所有必要空态、错误和恢复流程。
- 单条账户 Key 添加到 Magpie Provider，再用现有 Agent 接入流程选模型；以稳定来源标识去重。首版默认一条 Key 一个 Provider，不自动合并不同 Key；不影响用户原有多 Key Provider。
- 主站、Coding、GACCode 预设。Coding/GACCode 只手动填各自模型 Key，不增加登录、系统令牌或主站账户依赖。三类线路有各自购买/充值/查询网页入口。
- 兔子图片 API 接入 Magpie 现有生成/编辑工具、模型选择及 MCP/网关。先做兼容检查，已有能力满足时只配置和验证，不重复造轮子。
- 网站本地代码配套新来源和固定导航回跳，同时兼容兔子助手。网站尚未部署时，客户端能打开普通令牌页并手动返回，不强依赖线上新引导。
- 独立应用/配置/更新身份，防止原版数据及 Agent 配置被意外覆盖；原图标不动，许可证与上游归属保留；准备未来迁仓。

### 2.2 明确不做

- 新增 Web、CLI、TUI 账户管理界面；原有 Web、CLI、TUI、订阅、多 Provider、路由、MCP、Library、会话、用量、备份同步等继续可用。
- 从兔子助手导入配置、用户操作统计上报、查询网页自动填入 Key、客户端直接显示 Coding/GAC 额度。即使后来发现查询接口，也不在本轮自动追加内嵌额度功能。
- 账户资料设置、账户 OAuth/SSO、商城统一登录、客户端支付、订单、管理员控制台、完整请求/响应内容、批量 Key 或日志导出。
- 新建生图 Agent、生图页面或整套移植助手的 Codex 图片兼容逻辑。不因开发会话中的生图指令强制全产品用户使用一个模型/接口。
- push、PR、远程合并、标签发布、部署、生产迁移、线上配置修改、实际支付、付费模型调用、读取或使用真实账户凭证。

### 2.3 原有功能和界面的增量保护

允许的可见差异仅为：应用名称改成 tuzi-magpie；新增兔子账户导航入口及其页面/弹窗；新增主站、Coding、GACCode 预设及它们专属的配置、购买/查询入口；已确认的独立发行身份提示。原应用图标保持不变。

- 现有 Agents、Providers、路由、插件、Library/MCP、会话、Usage、设置、托盘及 Web/CLI/TUI 行为继续沿用；新增入口不能改变它们的默认选择、顺序、快捷键、操作步骤或既有持久偏好。若加入导航导致空间冲突，优先沿用上游布局机制解决，不自行重做侧栏。
- 原页面布局、字体、字号、颜色、间距、组件、表格、菜单、交互和文案保持原样，不顺带美化、统一视觉、更换框架/组件库或重构整个 app.js/CSS。新兔子页面沿用 Magpie 设计语言；兔子助手提供业务行为参考，不要求照搬其 React/Tauri 页面皮肤。
- 新样式限定在兔子容器/模块，避免全局 CSS/主题变量污染；复用上游组件时默认行为不变，不为新页面强制改变其他页面。新字段与持久数据采用兼容的缺省处理，保留未知/用户自定义字段。
- 除目标已经明确的独立应用/更新身份之外，网关核心、订阅/OAuth、路由算法、Agent 适配器及通用存储只在有证据证明接入必须时做最小修改，不借任务修复无关问题或改变默认策略。原有第三方 Provider 的地址、Key、模型、优先级不得自动迁移或改写。
- 开发前固定上游起点 SHA；用隔离合成配置记录原页面截图和代表性流程，覆盖相同尺寸、语言、主题、数据与运行条件。完成后比较同条件截图及行为，并记录差异原因。动态时间/数据和字体渲染噪声可解释排除，但不能掩盖布局或交互变化；不要求脆弱的全屏像素零差异。
- 主代理为每次涉及共享文件的修改说明必要性、受影响页面/功能及回归结果；最终审查须检查修改范围是否超出兔子接入。只测新增页面不算原功能无回归的证据。
- 若实现确需超出上述允许差异而改变原有界面、默认行为或用户数据处理，先准备具体的原因、替代方案、前后差异与影响，再向用户确认；确认前不实施该变化，继续独立任务。普通内部实现选择和已授权的新增内容不用逐项请示。

7. 若运行环境没有子代理能力，按同一任务表顺序完成；子代理不可用不是放弃任务的理由。

所有测试和预览使用隔离应用/Agent 配置目录、合成账户及上游。遵循 Magpie 当前 `docs/code-standards.md` 和 `LESSONS.md`，在任务开始复核实际命令。当前规范要求包含：gofmt、go vet、Linux/Windows vet/build、本机 build、`go test -tags nogui ./...`，以及按变更范围执行 Chromium/WebKit 和语言检查。账户/文件事务/并发增加相称的错误注入和 race 检查。新增界面/API 属跨页面风险，应执行规范要求的完整 GUI 回归。网站执行对应定向回归和构建。

本地端到端不能全由浏览器 mock 替代：需运行实际 Go 后端及网关，连合成服务，并验证写入的真实隔离配置。至少提供一次从构建出的桌面应用完成核心流程的证据。登记测试命令、环境、结果、最终 SHA 和产物，不写合成凭证值到公开交付说明。
